# 가이드 — 막힐 때 참고

## 단계별 명령
| 단계 | 명령 |
|:--|:--|
| 소스 검증(테스트) | `./gradlew test` |
| 클린 빌드(JAR 생성) | `./gradlew clean bootJar` → `build/libs/app.jar` |
| 검증+빌드+릴리스 보관 | `bash scripts/build.sh` |
| 운영 프로파일 실행 | `bash scripts/run.sh prod` |
| 헬스체크 | `curl http://localhost:9090/api/health` |
| Actuator 헬스 | `curl http://localhost:9090/actuator/health` |
| 롤백 | `bash scripts/rollback.sh 1.0.0` |
| 버전 확인 | `curl http://localhost:9090/api/version` |

## 프로파일 활성화 방법
- 실행 인자로 지정 : `java -jar build/libs/app.jar --spring.profiles.active=prod`
- 환경변수로 지정 : `SPRING_PROFILES_ACTIVE=prod java -jar build/libs/app.jar`
- prod 프로파일은 포트 **9090**, 지정하지 않으면 기본(dev) 포트 **8080** 으로 뜹니다.
- 활성 프로파일은 `/api/health` 응답의 `profile` 필드로 확인할 수 있습니다.

## 핵심 힌트
- 빌드 산출물 이름은 `app.jar` 로 고정되어 있습니다(build.gradle 의 `bootJar { archiveFileName = 'app.jar' }`). 스크립트가 이 이름을 참조하므로 바꾸지 않습니다.
- `build.sh` 는 검증(test) → 빌드(bootJar) → 릴리스 보관(`releases/app-<version>.jar`) 순서로 동작합니다. 롤백은 이 사본을 되돌려 놓는 방식입니다.
- 헬스체크는 "포트 → 엔드포인트 → 응답 필드" 순으로 확인합니다. 포트가 dev(8080)로 떠 있으면 prod 프로파일이 적용되지 않은 것입니다.
- 롤백 후에는 반드시 애플리케이션을 다시 실행하고 `/api/version` 으로 되돌린 버전이 맞는지 확인합니다.

## 배포 · 롤백 절차
1. `gradlew test` 로 소스를 검증합니다(실패하면 배포로 넘어가지 않습니다).
2. `gradlew clean bootJar`(또는 `build.sh`)로 `app.jar` 를 생성하고, 산출물 경로를 확인합니다.
3. `run.sh prod` 로 운영 프로파일 실행 후 `/api/health`·`/actuator/health` 로 정상 동작을 확인합니다.
4. 문제가 생기면 `rollback.sh <이전_버전>` 으로 이전 릴리스를 복원합니다.
5. 이전 버전을 다시 실행하고 `/api/version` 으로 복원 결과를 확인합니다.

## 실행 시 참고
- JDK 21 이 설치되어 있어야 합니다(`java -version`).
- 스크립트는 bash 기준입니다. Windows 에서는 Git Bash 또는 WSL 에서 실행합니다.
- 프로젝트가 한글 경로에 있으면 `gradlew`(명령줄)에서 클래스 로딩/인코딩 오류가 날 수 있습니다. 이때는 IntelliJ 의 Gradle 실행기로 돌리거나 영문 경로에서 실행합니다.
- 실행 중인 프로세스가 포트를 점유하고 있으면 재실행이 실패합니다. 기존 프로세스를 종료한 뒤 다시 실행합니다.

# 설계과제 — 애플리케이션 배포 (S-Deploy)

## 파트 A. 배포 환경 구성 (NCS 1)
- build.gradle 에서 다음을 확인·구성합니다.
  - Java toolchain 을 JDK 21 로 지정합니다.
  - Spring Boot 3.5.x 플러그인과 의존성 관리 플러그인을 사용합니다.
  - 실행 가능한 JAR 을 항상 같은 이름(`app.jar`)으로 생성하도록 `bootJar { archiveFileName = 'app.jar' }` 를 설정합니다. 배포 스크립트가 고정 이름을 참조하기 때문입니다.
- 환경(프로파일)을 분리합니다.
  - 기본(dev) : `application.properties` — 포트 8080, `app.env=dev`.
  - 운영(prod) : `application-prod.properties` — 포트 9090, `app.env=production`, 로그 레벨 INFO. 실행 시 `--spring.profiles.active=prod` 로 활성화합니다.
- 릴리스 보관용 배포 디렉토리(`releases`)를 준비합니다. 빌드 시 `releases/app-<version>.jar` 로 사본을 남겨 롤백에 대비합니다.

## 파트 B. 소스 검증 (NCS 2)
- `gradlew test` 로 소스가 정상 동작함을 확인합니다. 헬스 엔드포인트 테스트(`/api/health`, `/api/version`)가 통과해야 합니다.
- 배포 전 환경설정 값을 점검합니다.
  - 포트 : dev 8080 / prod 9090 이 프로파일별로 올바르게 지정되어 있는지 확인합니다.
  - 프로파일 : 활성 프로파일이 의도한 값(prod)으로 적용되는지 확인합니다.
  - 버전 : `app.version` 과 build.gradle 의 `version` 이 일치하는지 확인합니다.

## 파트 C. 빌드 (NCS 3)
- `gradlew clean bootJar`(또는 `scripts/build.sh`)로 `build/libs/app.jar` 를 생성합니다.
- 빌드 산출물의 경로와 크기를 확인하고, 빌드 로그에서 성공/실패 여부를 판단합니다.
- 빌드가 실패하면 로그를 근거로 원인(테스트 실패·컴파일 오류·의존성 문제 등)을 분석하여 `빌드_결과서.md` 에 기록합니다.
- `build.sh` 는 검증(test) → 빌드(bootJar) → 릴리스 보관(`releases/app-<version>.jar`)을 한 번에 수행합니다.

## 파트 D. 배포 · 롤백 (NCS 4)
- `scripts/run.sh prod`(내부: `java -jar build/libs/app.jar --spring.profiles.active=prod`)로 운영 프로파일 실행합니다.
- 배포 후 헬스체크로 정상 동작을 확인합니다.
  - `GET /api/health` → `status:UP`, `version`, `env`, `profile` 확인.
  - `GET /actuator/health` → Actuator 상태 확인.
- 문제 상황을 가정하여 롤백을 수행합니다.
  - `scripts/rollback.sh <이전_버전>` 으로 `releases/` 의 사본을 `build/libs/app.jar` 로 복원합니다.
  - 이전 버전을 다시 실행한 뒤 `GET /api/version` 으로 복원된 버전을 확인합니다.
- 배포·롤백 절차와 헬스체크 결과를 `배포_절차서.md`·`롤백_절차서.md` 에 기록합니다.

## 제약
- 추가 라이브러리 없이 Spring Boot 기본(starter-web, starter-actuator)과 Gradle Wrapper 만 사용합니다.
- Docker·외부 CI 도구·클라우드 배포는 사용하지 않고, 로컬에서 재현 가능한 배포 파이프라인으로 수행합니다.
- 빌드 산출물 이름(`app.jar`)과 스크립트 인터페이스(build/run/rollback)는 제공된 골격을 따릅니다.
- 테스트를 약화시키지 않고, 환경설정은 명세(포트·프로파일·버전)를 그대로 유지합니다.

> 참고 표준 : 배포 절차·롤백 계획은 형상관리(SCM)와 릴리스 관리 관점의 배포 실무 절차(빌드 산출물 버전 보관 → 배포 → 검증 → 실패 시 이전 버전 복원)를 따른다. 헬스체크는 Spring Boot Actuator 의 health 엔드포인트를 활용한다.

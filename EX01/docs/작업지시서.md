## ① 작업지시서(문제)

S-Deploy 프로젝트는 배포 검증용 REST 엔드포인트와 dev/prod 프로파일, 배포 스크립트 골격이 제공되는
Spring Boot 애플리케이션이다. 배포 환경(빌드 설정·프로파일·배포 디렉토리)을 구성하고, 소스 검증
(테스트·환경설정 점검)을 거친 뒤, 실행 가능한 JAR(app.jar)을 빌드하시오. 이어서 운영(prod) 프로파일로
애플리케이션을 실행하여 헬스체크(`/api/health`, `/actuator/health`)로 정상 동작을 확인하고, 문제가
발생한 상황을 가정하여 이전 버전으로 롤백한 뒤 정상 복원을 확인하시오. 각 단계의 명령·결과·산출물
문서를 제출하시오. (앱 소스·프로파일·배포 스크립트 제공)

---

## ② 내용(설명)

### [확인]
- 대상 앱   : S-Deploy — 헬스체크·버전 조회 엔드포인트를 가진 배포 실습용 애플리케이션
- 엔드포인트 : `GET /api/health`(status/version/env/profile), `GET /api/version`, `GET /actuator/health`
- 프로파일  : dev(기본, 포트 8080) / prod(포트 9090, `--spring.profiles.active=prod` 로 활성화)
- 빌드 산출물 : `build/libs/app.jar` (bootJar 이름 고정), 릴리스 사본 `releases/app-<version>.jar`
- 배포 절차  : 환경 구성 → 소스 검증(test) → 빌드(bootJar) → 실행(prod) → 헬스체크 → (문제 시)롤백
- 형상 관리  : 각 단계·산출물을 Git 커밋으로 이력 관리
- 환경      : JDK 21 / Spring Boot 3.5.x / Gradle / bash 스크립트
- 제공물    : 앱 소스(DemoApplication, HealthController), 테스트(HealthControllerTest),
              application.properties · application-prod.properties, build.gradle,
              배포 스크립트 3종(build.sh / run.sh / rollback.sh)
- 학생 구현  :
   · 배포 환경 구성 확인·정리 (build.gradle·프로파일·releases)
   · 소스 검증 수행 (gradlew test, 환경설정 점검)
   · 빌드 수행 (gradlew clean bootJar → app.jar)
   · 배포·헬스체크·롤백 수행 및 결과 확인
   · 산출물 4종 작성

### [핵심 수행 요구사항]

1) 배포 환경 구성(능력단위요소 ①)
   - build.gradle 의 JDK 21·Spring Boot 3.5·실행 가능 JAR(app.jar) 설정을 확인·정리
   - dev/prod 프로파일과 포트(8080/9090)를 분리 구성
   - 릴리스 보관용 배포 디렉토리(releases) 준비

2) 소스 검증(능력단위요소 ②)
   - `gradlew test` 로 소스가 정상 동작함을 확인(헬스 엔드포인트 테스트 통과)
   - 포트·프로파일·버전 등 환경설정 값이 명세와 일치하는지 점검

3) 빌드(능력단위요소 ③)
   - `gradlew clean bootJar` 로 `build/libs/app.jar` 생성
   - 산출물 경로와 빌드 로그(성공/실패)를 확인하고, 실패 시 원인을 분석

4) 배포(능력단위요소 ④)
   - `java -jar build/libs/app.jar --spring.profiles.active=prod` 로 실행(포트 9090)
   - `/api/health`·`/actuator/health` 로 정상 동작을 확인
   - 문제 상황을 가정하여 `rollback.sh` 로 이전 버전을 복원하고 `/api/version` 으로 확인
   - 배포환경_명세서·빌드_결과서·배포_절차서·롤백_절차서 작성
